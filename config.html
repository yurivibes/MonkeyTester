Build & Test

Build & Test builds a branch of your app on a build plugin's own host — a Mac builds Android and iOS, a Linux host Android only — and tests the result on the devices. A build plugin is a separate service that fetches the branch from Gitea or GitHub, runs the app repo's build scripts there and uploads the apps back to the viewer. Build plugins are registered on the Plugins page (Settings → Plugins, Build Plugin section); the plugin holds the code host's address and read-only token, and the viewer never sees that token.
RepoPluginBranchStatus
Each repo is a project: its runs are filed under it on the dashboard, it has its own Test Variables, and Build & Test can start a run from any of its branches. A repo belongs to one project, on one build plugin. The branch is the project's main line (e.g. master, main or develop), read through the plugin: Build & Test preselects it and the status check reads its test cases and build scripts. Building needs the app repo's per-platform build scripts (from the plugin's example scripts) committed on that branch; the status column names a missing one and links its example. Platforms the plugin's host can't build are greyed out in Build & Test.

Test Variables

Shared variables apply to every run. A project's variables apply only to its runs and override shared ones with the same name.
Every test can use these as ${KEY} / $KEY in step text and inside PLUGIN blocks — e.g. GET ${HUB_PATH}/devices -> … puts the saved path before the endpoint. Lines are KEY=value (# comments allowed, empty value legal). Read when a run starts: a change applies to the next run. A KEY=value line inside a test overrides the saved value.

CI token

CI jobs that upload apps with ci/mt-submit/submit.py send this token (MT_CI_TOKEN, sent as Authorization: Bearer). It only starts runs and reads their results; it opens nothing else. A new token is shown once: put it in the app repo's MT_CI_TOKEN secret. Admins only.

Service tokens

Tokens the viewer sends to the services it uses: the Mobile-Controller (X-Controller-Token) and each plugin (X-Plugin-Token). A token is checked against the service before it is saved. Stored in service_tokens.json (mode 0600, plaintext at rest) and never shown again — only its last 4 characters. Runs started afterwards use the new value. Admins only.

Appearance

Switches the viewer from the dark theme to a light theme. Applies immediately and is remembered.
